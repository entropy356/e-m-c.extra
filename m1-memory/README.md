# M1 记忆前端

把 `e-m-c.runtime` 跑成一个能玩的聊天前端，记忆库实现 M1 模型。

- **runtime**：单轮编排、SQLite 单事务提交、trace、模块协议（`e-m-c.runtime`）
- **模块**：`m1.memory`（agent 作用域，记忆库共享，跨轮指针按会话隔离）
- **认知**：`m1.toolcog.ToolLoopCognition` 替换 runtime 的 `direct`，带联网搜索的工具循环
- **前端**：原生 JS，回答下方是可折叠的运行链

## 跑

```bash
EMC_RUNTIME_PATH=../e-m-c.runtime/src ENV_FILE=~/agent-env.sh PORT=3000 ./run.sh
```

runtime 的查找顺序：本目录的 `vendor/`（自包含拷贝，发布时用）→ `EMC_RUNTIME_PATH` →
同级的 `../../e-m-c.runtime/src`。凭据走 `AGENT_CHAT_*`（对话）与 `AGENT_EMBED_*`（嵌入）。

## 记忆怎么长出来

每轮对话结束后，用户消息和回复各作为一份原文写入记忆（同一个 episode，互为经历邻接）。
「记忆库」面板可以直接贴一段话喂进去，立刻可检索。

## 联网搜索

模型可以在一轮的任意时刻自己决定搜索：它返回 `tool_calls`，后端执行搜索、把结果塞回
上下文、继续让它生成，直到给出正文（`m1/toolcog.py`）。

- 搜索源是 Tavily Search API（`m1/websearch.py`），取标题/链接/正文节选，不自己抓页面；需要 `TAVILY_API_KEY`。
- **不设降级源**：搜索失败如实报错，不拿劣质结果糊弄模型。
- 上限：每轮最多 5 次模型调用、4 次搜索；超了就让模型基于已有材料收尾。
- 搜索失败只作为工具结果反馈给模型，不会让整轮对话失败。
- 每次搜索的关键词、耗时、结果链接显示在运行链里，同时按 `turn_id` 存进 SQLite 的
  `search_traces` 表（独立表，不动 runtime 的 trace 结构）。

## 检索链

| 段 | 做什么 |
|---|---|
| 切块 | 600 码点窗口，重叠 80，步长 520 |
| 编码 | Gemini `gemini-embedding-001`，768 维，批量；失败回落到字符哈希 |
| 词法 | BM25（k1=1.2, b=0.75），NFKC + casefold，汉字单字与相邻双字 |
| 语义 | `[max(0, q̂·u)]^5` |
| 融合 | 两路各取前 15 归一化，`d = 0.65·lex + 0.35·sem` |
| 门控 | `γ = 0.16·max(0, 1−(d₁−d₂)/0.15)`，历史为空时 γ=0 |
| 扩散 | `a ← 0.27·v + 0.73·T·a`，L1 残差 ≤1e-9 或 100 步 |
| 取回 | `z = 0.57·d + 0.43·R·a`，取前 5 块 |

`B` 的每列由自身（κ=0.9）与最多 2 个正相似的前驱（按相似度分摊 0.1）组成；
`W = BBᵀ + 5·BABᵀ`，`A` 只连接同一 episode 内写入相邻的块。

## 看什么

- 每条回答下面的「运行链」：编码耗时、词法/语义候选、`d₁/d₂`、门控 `γ`、扩散步数与残差、
  每块的 `direct / neural / total`。
- 右侧「记忆库」：块列表、上一轮留下的激活指针 `p`、直接写入。

## 已知边界

- 对话模型 `deepseek/deepseek-v4.1-flash` 是带推理的模型，`max_tokens` 给小了会返回空；配置里给到 1600。
- 免费/低配渠道有 5 次/分钟的限流，连续对话可能撞 429，runtime 会重试三次。
- 嵌入走 Gemini，单轮两次请求（查询 + 写入批），失败时自动回落到哈希编码，trace 里会标 `fallback`。
